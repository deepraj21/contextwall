Prompt Safety

Stop secrets before they leave your runtime.

A TypeScript-first utility that intercepts API keys, tokens, PII, and secrets from strings before they are sent to any AI provider. 100% local, zero-dependency, and works with any LLM SDK.

npm install contextwall Explore API
  • Zero network calls
  • Zero runtime dependencies
  • Browser-safe core
  • ESM + CJS output

The Problem

// You write this
const { text } = await generateText({
  model: 'anthropic/claude-sonnet-4-5',
  prompt: `Here is the api key rsk_124321, use it to call the payments API`,
});

// rsk_124321 just left your app and is now in:
// - provider request logs
// - observability tools
// - third-party SDKs on request path
// - possible fine-tuning datasets

The Problem

Prompt payloads often carry high-risk data accidentally. Without interception, that data can spread across provider logs, observability systems, middleware, and debugging pipelines.

API keys leak quickly

Keys like sk_, rsk_, and cloud credentials are easy to paste into prompts.

PII exposure compounds risk

Email addresses, phone numbers, and payment info can unintentionally enter third-party processing.

Sanitization is often inconsistent

Ad hoc regex logic in each service leads to coverage gaps and hard-to-audit behavior.

The Fix

import { promptwall } from 'contextwall';

const { text } = await generateText({
  model: 'anthropic/claude-sonnet-4-5',
  prompt: promptwall(`Here is the api key rsk_124321, use it to call payments API`),
});

// Prompt sent:
// "Here is the api key [API_KEY], use it to call payments API"

Local by default

All detection and replacement happen in-process with no telemetry.

Deterministic safety net

Regex and policy-driven behavior makes outcomes predictable and testable.

Flexible integration surface

Use direct APIs, middleware, integrations, or stream transforms depending on your architecture.

API Reference

promptwall(text, options?)

const clean = promptwall('token sk_live_abc and john@acme.com');
// -> "token [API_KEY] and [EMAIL]"

dewall(text, context)

const { text, context } = promptwall('sk_live_abc', { strategy: 'tokenize' });
const restored = dewall(result.text, context);

auditwall(text, options?)

const report = auditwall('auth: rsk_xyz, email: john@acme.com');
// report.detections, report.riskScore

createwall(config)

const mywall = createwall({ strategy: 'semantic', detectors: ['api_keys'] });

batchwall(prompts, options?)

const cleaned = batchwall(['Key: sk_live_abc', 'Email: john@example.com']);

schemawall(obj, options?)

const safe = schemawall([{ role: 'user', content: 'key sk_live_abc' }]);

streamwall(options?)

await pipeline(promptReadable, streamwall({ strategy: 'placeholder' }), llmWritable);

policywall(text, policy)

const safe = policywall('key: rsk_abc, email: a@b.com', { API_KEY: 'block', default: 'redact' });

logwall(text, options?)

const clean = logwall('api: sk_abc', { logger: (event) => console.warn(event.type) });

Custom Detectors

const wall = createwall({
  customRules: [
    { name: 'STRIPE_WEBHOOK_SECRET', pattern: /whsec_[a-zA-Z0-9]{32,}/g, severity: 'critical', replace: '[STRIPE_WEBHOOK_SECRET]' },
    { name: 'INTERNAL_USER_ID', pattern: /USR-[0-9]{8}/g, severity: 'low', replace: () => 'USR-[REDACTED]' },
  ],
});

Security Model

  • Entirely local execution, no network calls.
  • No data storage and no telemetry.
  • logwall() never emits original secret values.
  • Tokenized context remains in-memory only unless you persist it.

Limitations

  • Not a substitute for secrets management.
  • Regex-based detection may miss novel/obfuscated formats.
  • dewall() requires the original in-memory tokenization context.
